# 03-10-2026

Vortex TSDB 2.0 后端（`backend/tsdb-service`）：基于 Spring Boot 4.1 和 openspreader 重写。

## 新增

- 存储建在 openspreader 的复制缓存上：每个 series 每分钟一个 STATS 聚合 bucket
  （`tsd:<type>:<category>:<dimension>:<bucketStart>`，max/min/sum/count，保留期作为 TTL）；
  每个 series 的最新值存在 `tsd:last:<category>`；series 目录存在 `tsd:catalog`。
- 保留 v1 接口：`/tsd/push`、`/tsd/test`、`/tsd/retrieve`，参数 `t`/`c`/`d`/`v`/`z`，
  以及 `ApiResult` 包装（code 1/0）。
- 新接口：`/tsd/last`、`/tsd/query`（range、step、滚动或滑动 `window`、时区）、
  `/tsd/category`、`/tsd/categories`（按繁忙程度降序）、`/tsd/series`、`/tsd/cluster`、
  `/tsd/health`、`/tsd/health/self`。Swagger UI 位于 `/swagger-ui.html`。
- 持久化：openspreader 缓存在停机时及每隔 `VORTEX_SNAPSHOT_INTERVAL`（默认 5m）写盘。
- 可选的 Redis 溢出：设置 `VORTEX_REDIS_HOST` 时，超过 `VORTEX_CACHE_MAX_KEYS`（默认 10,000）
  的 key 通过 `RedisCacheStore` 转存到 Redis；未设置时排除 Redis 自动配置（`RedisSwitch`）。
- 集群健康：每个节点每 5 秒把 API 速率、`/actuator/spreader` 的缓存与复制指标、JVM 指标写入
  复制哈希 `tsd:health`。
- 未设置 `VORTEX_SERVER_PORT` 时，HTTP 端口在 `VORTEX_PORT_RANGE`（50000-60000）内随机选取，
  启动时打印地址。
- 所有配置项均为 `VORTEX_*` 变量，从 `backend/tsdb-service/.env` 读取（参见 `.env.example`）。
- Dockerfile 带健康检查；优雅停机。
- 测试：60 个，JaCoCo 门槛为行与分支覆盖率 80%（实测约 98% / 93%）。Redis 溢出测试连接本机
  Redis，本机没有 Redis 时跳过。

## 修复

- 有 12,000 个空闲 series 时 `/tsd/categories` 耗时 10.4 秒：每个不存在的 bucket 都去 Redis
  查一次。现在跳过晚于目录中该 series 最后采样时间的 bucket（约 0.03 秒）。
- openspreader 不会创建 `RedisCacheStore`（它的自动配置先于 Boot 的 Redis 自动配置执行）；
  用 `ExternalCacheStoreConfig` 绕过。

## 移除

- 确认功能全部覆盖后，删除 v1 模块（`vortex-spring-boot-starter`、`vortex-tsdb-web`）、
  doodler transmitter 以及 `history/` 目录。
